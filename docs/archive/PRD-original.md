# PRD — تطبيق «جيبي»

## 1. تعريف المنتج

**اسم التطبيق:** جيبي  
**الاسم الإنجليزي الداخلي:** Jibi  
**المنصة الأولى:** Android  
**التقنية:** Flutter / Dart  
**نوع التطبيق:** Local-first / Offline-first  
**قاعدة البيانات:** SQLite محلية مع تشفير البيانات الحساسة  
**النسخ الاحتياطي:** Google Drive  
**لغة الواجهة الأساسية:** العربية RTL  
**اللغة الثانية مستقبلاً:** الإنجليزية

### فكرة التطبيق

«جيبي» هو تطبيق محفظة شخصية آمنة تجمع ثلاثة أقسام رئيسية في تطبيق واحد:

1. الحسابات الشخصية والديون والمصاريف.
2. خزنة أسماء المستخدمين وكلمات المرور.
3. محفظة المستندات والصور والملفات الشخصية.

يجب أن تعمل جميع الوظائف الأساسية بدون إنترنت.

الإنترنت مطلوب فقط عند:
- تسجيل الدخول إلى Google.
- إنشاء نسخة احتياطية.
- استعادة نسخة احتياطية.

# 2. أهداف المنتج

يجب أن يمكّن التطبيق المستخدم من:

- معرفة من له مال ومن عليه مال.
- تسجيل السلف والمدفوعات والمصاريف.
- التعامل مع أكثر من عملة.
- معرفة رصيد كل شخص بصورة مستقلة.
- حفظ كلمات المرور وبيانات الدخول بأمان.
- حفظ صور البطاقات والجوازات والمستندات.
- البحث السريع في جميع البيانات.
- حماية التطبيق ببصمة أو رمز قفل.
- الاحتفاظ بجميع البيانات محلياً.
- إنشاء نسخة احتياطية مشفرة.
- رفع النسخة المشفرة إلى Google Drive.
- استعادة جميع البيانات على هاتف جديد.

# 3. المبادئ الأساسية للتطبيق

يجب الالتزام بالمبادئ التالية:

### Privacy First

لا يتم إرسال محتوى المستخدم إلى أي خادم تابع للتطبيق.

### Local First

قاعدة البيانات الأصلية موجودة على جهاز المستخدم.

### Offline First

التطبيق يعمل بالكامل دون اتصال بالإنترنت باستثناء Google Drive.

### Encryption First

أي بيانات حساسة يجب تشفيرها قبل تخزينها أو نسخها احتياطياً.

### Simple UX

يجب ألا تتحول ميزات الأمان إلى واجهة معقدة.

# 29. الأمان

هذا جزء إلزامي وليس اختيارياً.

## Master Encryption Key

إنشاء مفتاح تشفير عشوائي قوي عند أول تشغيل.

لا يتم تخزين المفتاح كنص عادي في:

- SharedPreferences.
- SQLite.
- ملفات التطبيق.

يتم حفظ المفتاح أو مفتاح تغليفه باستخدام Android Keystore / Secure Storage.

---

# 30. حماية كلمات المرور

حقول Password Vault الحساسة يجب أن تكون مشفرة.

لا يسمح بأي Password داخل:

- logs.
- crash reports.
- debug output.
- analytics.

---

# 31. حماية المستندات

كل ملف يتم تخزينه مشفراً.

استخدم تشفير authenticated encryption مثل:

AES-256-GCM

مع:

- IV/Nonce عشوائي مستقل لكل ملف.
- Authentication tag.
- عدم إعادة استخدام nonce مع نفس المفتاح.

---

# 32. حماية قاعدة البيانات

استخدم SQLite/Drift كطبقة بيانات.

لكن يجب ضمان تشفير المحتوى الحساس بواسطة أحد تصميمين معتمدين:

### الخيار A

SQLite مشفرة بالكامل باستخدام SQLCipher/SQLite encryption مناسب للإصدار الحالي.

### الخيار B

SQLite عادية داخل Sandbox التطبيق مع تشفير الحقول الحساسة على مستوى التطبيق.

في جميع الحالات:

- كلمة المرور نفسها مشفرة.
- معلومات الوثائق الحساسة مشفرة.
- الملفات مشفرة بشكل مستقل.

لا تعتمد على Sandbox Android وحده لحماية Vault.

# 41. كلمة مرور النسخة الاحتياطية

يجب حل مشكلة استعادة البيانات عند فقد الهاتف.

المفتاح الموجود في Android Keystore على الهاتف القديم لن يكون موجوداً على الهاتف الجديد.

لذلك يجب استخدام:

**Backup Password / Recovery Password**

يختارها المستخدم عند تفعيل النسخ الاحتياطي لأول مرة.

يتم اشتقاق Backup Encryption Key منها باستخدام KDF قوية مناسبة.

لا يتم رفع كلمة المرور نفسها إلى Google Drive.

يجب تحذير المستخدم بوضوح:

«إذا فقدت كلمة مرور النسخة الاحتياطية فلن يمكن استعادة بياناتك.»

# 66. Acceptance Criteria — الحسابات

الميزة تعتبر مكتملة عندما:

- يمكن إنشاء شخص.
- يمكن تعديل الشخص.
- يمكن حذفه أو أرشفته.
- يمكن إضافة عملية.
- يمكن تعديل العملية.
- يمكن حذف العملية.
- الرصيد يعاد احتسابه بشكل صحيح.
- كل عملة تظهر مستقلة.
- تغيير عملية قديمة يحدث الرصيد الحالي.
- التطبيق يحافظ على الدقة المالية.

# 67. Acceptance Criteria — كلمات المرور

الميزة مكتملة عندما:

- يمكن إضافة Credential.
- password لا يخزن كنص واضح.
- يمكن إظهار كلمة المرور بعد فتح Vault.
- يمكن نسخ كلمة المرور.
- يمكن تعديلها.
- يمكن حذفها.
- البحث يعمل.
- التطبيق لا يسجل Password في Logs.
- شاشة Vault محمية من Screenshots عند تفعيل الحماية.

---

# 68. Acceptance Criteria — المستندات

الميزة مكتملة عندما:

- يمكن اختيار صورة.
- يمكن التصوير بالكاميرا.
- يمكن اختيار PDF أو ملف.
- الملف ينسخ إلى مساحة التطبيق.
- الملف المخزن مشفر.
- يمكن عرضه بعد فك التشفير.
- يمكن حذفه.
- حذف المستند يحذف ملفاته الفعلية.
- المستندات تدخل ضمن Backup.
- المستندات تعود سليمة بعد Restore.

# 69. Acceptance Criteria — Backup

Backup مكتمل فقط عندما ينجح الاختبار التالي:

1. إنشاء حسابات.
2. إنشاء عمليات مالية.

4. إضافة عدة صور ومستندات.

8. تسجيل Google.

# 70. اختبارات الأمان

اختبر أن:

- ملف SQLite لا يكشف كلمات المرور.

# 76. تعليمات إلزامية لوكيل الذكاء الاصطناعي

عند تنفيذ المشروع:

1. لا تنفذ المشروع كله في Commit واحد.

2. نفذ Feature واحدة في كل مرحلة.

3. قبل كتابة الكود:
   - اشرح الملفات التي ستتغير.
   - اشرح الـData Model.
   - اشرح الـSecurity implications.

4. بعد كل Feature:
   - شغل `flutter analyze`.
   - شغل الاختبارات.
   - أصلح الأخطاء.
   - لا تنتقل للمرحلة التالية مع Tests فاشلة.

5. لا تستخدم Packages مهجورة.

6. تحقق من أحدث إصدار وتوثيق رسمي لكل Dependency قبل إضافتها.

7. لا تخزن Secrets داخل Repository.

8. لا تضف Google Client Secrets داخل Git.

9. لا تخزن encryption keys في Dart constants.

10. لا تخزن Password/PIN في SharedPreferences.

11. لا تطبع بيانات حساسة في Console.

12. لا تنفذ تشفيراً Cryptographic Algorithm من الصفر.

13. استخدم مكتبات تشفير موثوقة ومعايير معروفة.

14. افصل:
    - Encryption.
    - Database.
    - Google Drive.
    - UI.

15. كل Database migration يجب أن تكون قابلة للاختبار.

## تنبيهات انتهاء الوثائق

للمستندات التي تحتوي expiryDate:

يستطيع المستخدم اختيار تنبيه:

- قبل يوم.
- قبل أسبوع.
- قبل شهر.
- قبل 3 أشهر.

مثلاً:

«تنتهي صلاحية جواز السفر بعد 30 يوماً.»

# 81. تصميم واجهة التطبيق

الهوية المقترحة:

- بسيطة.
- عربية.
- حديثة.
- مالية لكن غير مشابهة لتطبيق بنكي رسمي.
- إحساس بالخصوصية والأمان.

الشعار:

فكرة تجمع بين:

جيب / محفظة + قفل.

واجهة الصفحة الرئيسية يجب ألا تكون مزدحمة.

# 82. معيار النجاح النهائي

يعتبر «جيبي» ناجحاً عندما يستطيع المستخدم الاعتماد عليه كتطبيق واحد بدلاً من:

- دفتر ديون.
- تطبيق ملاحظات لكلمات المرور.
- مجلد صور للمستندات.

مع ضمان أن بياناته:

**تبقى ملكه، محفوظة محلياً، ومشفرة، ويمكن استعادتها عند تغيير الهاتف.**
